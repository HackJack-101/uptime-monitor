Features

Everything a team needs to watch its services

Built for agencies, freelancers and small teams who run many sites for many clients, and want one place to watch them all.

Thorough checks

Status codes, keywords, Basic / Bearer / API-key auth for HTTP. SSH with an optional health-check command. DNS answers and certificate expiry.

Organised by project

Each project holds its own monitors, notification channels, rules and members. Perfect for one project per client or per product.

Users & access control

A superadmin, admins, and users invited to the projects they need, as viewer or editor. Other projects stay invisible to them.

Flexible check rules

Interval, timeout, retries and a "degraded" response-time threshold. Set defaults per project and override them per monitor.

Smart notifications

Pick which events go where: down, recovered, degraded, certificate expiring. Failure thresholds and reminders avoid noise.

OVHcloud DNS zone view

Connect a read-only OVH token and see every host of a zone: running, in error, or not monitored at all. One click adds the missing monitor.

Response-time charts

From the last hour to the last 30 days, with outages highlighted, plus uptime percentages for every monitor.

Incident history

Every outage is recorded with its start, end and cause. The dashboard shows what is broken now and what broke this week.

Works everywhere

A live dashboard that fits phones, tablets and desktops, in light or dark mode, in English or French, with a built-in guide.

Alerts

Get told where you already are

Send each project's alerts to its own channels. Every channel is free to use, and you can add as many as you like.

  • No false alarms: retries and failure thresholds confirm an outage before anyone is woken up.
  • No forgotten outages: reminders repeat while a service stays down.
  • Scoped rules: a rule applies to a whole project or to a single monitor.

Projects & teams

Share the dashboard, not the keys

Give a client read-only access to their own project, let a developer manage the monitors of theirs, and keep everything else private.

  • Inheritance: monitor setting → project default → global default.
  • Audit log of sign-ins and of every change to users, projects, monitors, channels and rules.
  • Your language: each user picks English or French, and light, dark or system theme.

Security

Your credentials deserve better than plain text

Monitoring means storing passwords, tokens and keys. Uptime Monitor treats them as secrets from end to end.

Encrypted, write-only secrets

HTTP credentials, SSH keys, webhook URLs and bot tokens are encrypted with AES-256-GCM. The API never sends them back.

Hardened sign-in

scrypt password hashing, HTTP-only SameSite cookies, CSRF protection and rate-limited login. Sessions are revoked when a password or role changes.

Safe checks

SSH host key pinning, credentials never forwarded across redirects, secrets masked in error messages, and a container running unprivileged behind a strict CSP.

Get started

Up and running in five minutes

One container, one volume, one SQLite database. No external service to run alongside it.

Deploy the image

Paste the docker-compose.yml into a Portainer stack, or run the command below. The image runs on amd64 and arm64.

Create the superadmin

Open the UI and paste the one-time setup token printed in the container logs.

Add your first project

Create a project, add monitors and channels, and invite your team. The built-in guide walks you through it.

docker run -d --name uptime-monitor --restart unless-stopped \ -p 3000:3000 -v uptime-data:/data \ -e APP_SECRET="$(openssl rand -base64 48)" \ ghcr.io/hackjack-101/uptime-monitor:latest # Then open http://localhost:3000 and read the setup token in the logs: docker logs uptime-monitor

Keep APP_SECRET safe: it encrypts every stored secret. Serve the app over HTTPS behind your reverse proxy in production.
